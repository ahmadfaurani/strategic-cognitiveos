# Risk Description

The deployed working tree is the recorded basis commit with 8 further files applied additively on top of it — not a clean checkout of any single commit. 43 uncommitted modifications are present, including the runtime composition file. A release manifest generated from the repository alone will misdescribe the deployment.

Additional findings:
- No migration ledger exists on the deployment
- Two migrations are pending, one of which (organisation backfill) must precede the application release
- The deployment is 29 commits / ~40 days behind the trunk
- The deployment does not satisfy build-identity control

## Risk Category

Technical debt + release integrity — the deployment is not describable by any single revision.

## Probability & Impact

- **Probability:** Occurred — the deployment IS in this state right now
- **Impact:** High — no release can be safely verified against an undescribable deployment; migrations applied without a ledger are uncontrolled schema changes to persistent evidence

## Mitigation Strategy

**Phase 0, Deliverables 0.3 + 0.4 + 0.5:**

1. **M3 — Reconstruct manifest** (0.3): Build the release manifest file by file, listing every file, its origin and destination state. Approved by a named owner.
2. **M4 — Prove recovery** (0.4): Take full backup of database and evidence volumes. Restore into isolated target. Verify by sampling cases, evidence, attribution, sanctions and audit rows. MUST precede migrations.
3. **M5 — Apply migrations** (0.5): Apply organisation backfill migration first (prevents 6 cases from becoming invisible to reviewers), then audit-enforcement migration. Through the migration runner with checksums and ledger.

**Sequencing:** M4 (restore) → M5 (migrations) → M6 (deploy). Migrations alter persistent evidence — an unrehearsed restore is not a rollback plan.

## Trigger Conditions

- Release attempted against undescribable deployment
- Migration applied without ledger entry
- Organisation backfill skipped — 6 cases lose visibility to reviewers
- Backup cannot restore when needed during incident
