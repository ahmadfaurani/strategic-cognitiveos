# Risk Statement

GovSec TIP has been in active feature development for ~5 months (v1.0 → v3.0) without a dedicated security hardening cycle. The platform is a cybersecurity product that will be demonstrated to cybersecurity professionals, government agencies, and CNII sector stakeholders at CyberDSA October 2026. If the platform itself has unmitigated vulnerabilities, this creates a credibility risk that undermines the product's core value proposition.

The development freeze (DEC-20260810-002) includes "close critical technical/security gaps" as Priority 2, but no security assessment or penetration test has been scheduled yet.

# Risk Owner

DAF (Director, Cyber Security Practice) — owns the security posture decision for the product launch.

# Affected Initiatives

- INIT-20260810-003 — GovSec CyberDSA Product Launch Readiness (Priority 2: close critical security gaps)
- INIT-20260804-003 — GovSec × TI Integration (integration security)

# Likelihood

High — 5 months of rapid development without hardening. React + Node.js + PostgreSQL stack with RAG AI integration, MITRE TAXII 2.1 connector, and multiple API endpoints. No documented security testing, code review, or penetration testing.

# Impact

Critical — demonstrating a cybersecurity product with discoverable vulnerabilities at a cybersecurity conference would be a catastrophic credibility failure. Additionally, the platform handles threat intelligence data, government org structure information, and Malaysian APT library data — potential PII exposure under PDPA.

# Mitigation

1. **Security assessment before CyberDSA** — schedule a security review/penetration test of the v3.0 build before October
2. **Code review of demo-critical paths** — at minimum, review the authentication, API endpoints, and data display flows that will be demonstrated
3. **PDPA compliance audit** — verify that the PDPA features (PII detection, redaction, audit, retention) actually work as documented
4. **Dependency scan** — run dependency vulnerability scan (npm audit, PostgreSQL CVE check) and remediate critical findings
5. **Demo environment isolation** — ensure the demo environment is isolated from any production data and hardened against conference-network attacks

# Monitoring

- Security assessment results (pre-CyberDSA)
- Any vulnerability discovered during stabilisation/hardening phase
- Dependency scan results

# Status

Active — risk identified during risk register review. No security assessment has been scheduled yet. This should be added as an explicit action under INIT-20260810-003 Priority 2.
