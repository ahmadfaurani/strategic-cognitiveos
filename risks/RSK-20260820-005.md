# Risk Description

Four supplier credentials were served to unauthenticated callers for approximately 32 days. The handler defect that exposed them is fixed in code and the fix is deployed, but the credentials themselves were confirmed unrotated on 19 August 2026.

The exposure window has already elapsed. The fix prevents future unauthorized access but does not invalidate the already-compromised credentials. They must be revoked and reissued at the provider level.

## Risk Category

Security exposure — credentials compromised, rotation pending.

## Probability & Impact

- **Probability:** Occurred — the exposure is confirmed, not theoretical
- **Impact:** Critical — credentials provide access to supplier APIs; unauthorized use could compromise intelligence sources or incur costs

## Mitigation Strategy

**Phase 0, Deliverable 0.1 (M1 on critical path):**
1. Revoke and reissue the four supplier credentials at the provider
2. Update deployment configuration with new credentials
3. Verify rotation by changed masked fingerprints in key-health output
4. Confirm old values are rejected by the providers

**Non-negotiable sequencing rule:** Rotation precedes any widening of reachability. The private-network boundary is currently the only containment. Making the platform easier to reach before closing the exposure inverts the risk.

## Trigger Conditions

- Any anomalous API usage from the four suppliers before rotation completes
- Credentials used by unauthorized party
- Supplier reports unusual access patterns

## Capacity Risk

If one person holds both security and platform-ops roles, Phase 0's 5-day sequential window expands. This is the largest schedule risk in the roadmap.
