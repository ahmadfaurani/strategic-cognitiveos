# Action

Develop the Cyber Security Practice hiring plan from workstream demand rather than from pre-selected job titles alone.

## Required Output

For each active or committed workstream, map:
- Delivery scope and expected workload
- Capability required
- Required FTE or fractional FTE
- Current named coverage and available capacity
- Capacity gap
- Proposed role or staffing response
- TBH Registry ID where the gap represents a role-to-be-hired
- Priority, timing and dependency

## Governance Rule

The TBH Registry remains the canonical hiring-gap register. The capacity model is the evidence layer that justifies why each TBH role exists, how much capacity is required, and which workstreams it blocks.

## Timeline

Work in progress through **30 September 2026**. Existing HoE, CSE and Junior Backend actions remain inputs to the model, but the final hiring plan is governed by workstream-to-FTE evidence.
