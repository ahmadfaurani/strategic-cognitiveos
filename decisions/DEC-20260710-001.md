# Context

A single merged Voron-Campaign repository contained both RMiT compliance materials (250 BNM-regulated financial institutions) and HOI intelligence materials (100 government agencies, OSINT briefs, PRN Johor 2026 data). The merged repo had 304 files mixing two distinct operational domains, making navigation, contribution, and access control harder.

# Decision

Split the merged repository into two focused repositories:

1. **Voron-Campaign** (https://github.com/ahmadfaurani/Voron-Campaign) — RMiT compliance, 143 FIs, 1,001 stakeholders, battle cards
2. **HOI-Intelligence-Operations** (https://github.com/ahmadfaurani/HOI-Intelligence-Operations) — 100 agencies, 10 PIRs, 32 daily briefs, PRN Johor 2026

Backup preserved at `/home/p62operator/.openclaw/workspace-backup-20260710-151547/` (11MB, 304 files).

# Rationale

- Two distinct operational domains with different stakeholders, access patterns, and content types
- Cleaner contribution workflows — each repo has focused .gitignore, README, and structure
- Access control granularity — different sensitivity levels for compliance vs intelligence
- Reduces cognitive load when navigating either domain

# Alternatives Considered

- **Keep merged, use directory structure** — Maintain single repo with clear top-level directories. Rejected: Still mixes git history, access control, and contribution workflows. Directory structure doesn't solve the core issues.
- **Split into three (add PI-OS as third)** — Separate PI-OS at the same time. Rejected: PI-OS didn't exist yet (2026-07-10). Premature. PI-OS created later as separate repo on 2026-07-24.

# Assumptions

- Both repos will continue to be developed independently
- Backup is sufficient for recovery (verified: zero data loss, file counts confirmed)

# Consequences

- Cross-referencing requires full URLs or external links
- Each repo maintains its own README, .gitignore, and structure
- Clean separation validated: no cross-contamination
