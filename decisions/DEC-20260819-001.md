# DEC-20260819-001 — Halt Hermes Embedding Backfill; cognitiveos Workspace is Deriver Target

## Decision

Halt the Hermes deriver queue processing. The `cognitiveos` workspace is the deriver's consumption target, not the Hermes embedding backfill. The 486 pending Hermes work units are frozen and irrelevant to this path.

## Rationale

- Hermes workspaces are established and do not require further deriver processing for the CognitiveOS integration
- The deriver processes each workspace independently — `cognitiveos` is a new, separate workspace
- Continuing the Hermes backfill would consume deriver capacity needed for `cognitiveos` ingestion
- The embedding infrastructure (TEI bge-m3, 1024-dim) is operational and ready for `cognitiveos` use

## Implementation

- `docker stop honcho-deriver-1` executed 2026-08-19 03:09 UTC
- Deriver to be restarted when Phase 2 batch ingestion begins
- Hermes workspaces remain untouched (isolation principle)
