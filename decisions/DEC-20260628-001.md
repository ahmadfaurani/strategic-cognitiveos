# Context

In long-form political analysis, factual claims (numbers, names, dates) can drift through inference, hallucination, or conflation. Without a validation system, analytical outputs carry unverified claims that could mislead decision-making. The Johor PRN war room briefs (2026-06-27) exposed this risk — demographic numbers, historical results, and candidate details needed multi-source verification.

# Decision

The Core Truth Validation System (CVS) is MANDATORY across all sessions, all outputs, and all agents. No exceptions.

**Five rules:**

1. **Multi-Source Verification** — All Tier 1 claims require ≥2 independent sources + citation
2. **Confidence Assertion Tags** — All analytical claims tagged [HIGH] / [MEDIUM] / [LOW]
3. **Speculation Demarcation** — All predictive claims flagged SPECULATION: or SCENARIO:
4. **Conflict Resolution** — When sources disagree, tag [CONFLICTING], show both, request human review
5. **Validation Gate** — All output must pass `./tools/truth-validator/validate.sh`

# Rationale

- Political intelligence outputs directly inform assessments about real candidates and real voters
- Unverified claims compound — a wrong demographic figure skews turnout models and strategic recommendations
- The system needs to be trustworthy by design, not just trustworthy by intention
- "Honesty is architecture, not decoration" — verification must be structural, not optional

# Alternatives Considered

- **Spot-check verification (manual)** — Verify claims only when they seem suspicious. Rejected: Reactive, not preventive. Misses subtle drift. Inconsistent enforcement.
- **External fact-checking service** — Route outputs through external API for verification. Rejected: Privacy concerns (political content to third parties), latency, cost, and Malaysian-specific context not well-covered by general fact-checkers.
- **Confidence tagging only (no source requirement)** — Tag claims with confidence but don't require source citations. Rejected: Tags without sources are performative. "MEDIUM confidence" means nothing if you can't check the basis.

# Assumptions

- The validation tools (`tools/truth-validator/`) will be maintained and kept functional
- DAF has final authority to override any CVS block in real-time
- The system applies to analytical outputs, not to casual conversation

# Evidence

- Johor PRN war room briefs (2026-06-27) exposed verification needs — documented in CONV-20260627-001
- CONV-20260628-001 — conversation establishing CVS mandate
- `tools/truth-validator/` validation infrastructure implemented and operational
- ElectionData.MY API integrated (2026-06-29) for Malaysian elections cross-referencing

# Expected Outcome

All analytical outputs include citations, confidence tags, and pass validation before delivery, producing trustworthy intelligence products that inform real-world decisions about real candidates and voters. Monthly compliance reviews tighten gates over time, reducing error rates systematically.

# Consequences

- All long-form analytical outputs now require explicit citations and confidence tags
- Outputs can be blocked by the validation gate before delivery
- Monthly reviews may tighten gates based on compliance data
- Increases output preparation time but dramatically improves reliability

# Risks Accepted

- **Validation tool failure blocks all output** (high severity) — Mitigation: DAF can override; fix tool, don't bypass system
- **Over-tagging makes outputs unreadable** (medium severity) — Mitigation: Tags are structured (not inline prose); review monthly
- **False confidence in CVS as guarantee** (medium severity) — Mitigation: CVS reduces error, doesn't eliminate it. Human review still required.
