# Lesson

## Observation

When a leader is overloaded, the instinct is to create a role that absorbs everything the leader is doing. But the approved operating model may have already assigned some of those functions to other roles that are also unfilled.

In TBH-001's case: the PM role was assigned roadmap, backlog, and product governance responsibilities. But the operating model treats Technical Product Manager (TPM) as a separate P1 role — responsible for roadmap, backlog, release plans, requirements, and demo readiness. If the PM absorbs TPM scope, the PM becomes the next single point of failure.

## Pattern

**SPOF displacement:** Solving one SPOF by creating another. The Practice Lead is the current SPOF — overloaded with PM functions. If TBH-001 absorbs both PM AND TPM scope, TBH-001 becomes the next SPOF. The fix creates the problem.

## Corrective Action

For every TBH role:
1. Check the approved operating model for all P1 roles and designated responsibilities
2. Map each proposed responsibility to the correct role
3. If a responsibility belongs to another unfilled P1 role → scope as "coordinate/facilitate" not "own"
4. Include explicit boundary exclusions in the job description
5. Test: if this person leaves, what breaks? If the answer is "everything", the scope is too broad

The PM/TPM boundary principle: **PM coordinates the process; TPM owns the content.**
