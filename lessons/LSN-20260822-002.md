# Lesson

## Observation

Ember was asked to review an email trail. In the initial summary, Ember stated "CSM never confirms the Aug 12-14 dates" as fact. This was wrong — CSM confirmed Aug 14, and training was delivered that day at the Meranti Meeting Room. The confirmation and delivery were recorded in four separate memory files that existed before this session began.

Ember inferred status from the absence of confirmation in the email trail snippet being reviewed, without checking whether the confirmation (and delivery) were already recorded elsewhere in memory.

## Pattern

This is the same root pattern as LSN-20260821-007 (missed "that's it" 4x): **Ember processes the current message without checking existing records first.** The information exists in memory but is not consulted before making a claim.

The pattern has now been captured three times. At DAF's directive (Aug 22 07:37 UTC), LSN records are mandatory deriver-qualified items — every lesson must go through the memory pipeline and become part of core memory, not just a file on disk.

## Root Cause

Ember treats the current message as the primary source and memory as supplementary. This is backwards for a system with persistent memory. Memory should be the primary source; the current message is new information to be integrated.

## Corrective Action

Before stating any claim about past events, records, or status:

1. **Check own memory first** — grep for the topic, read relevant records
2. **If records exist, use them as the source** — cite the file and what it says
3. **If records don't exist or are ambiguous, flag as unverified** — "I don't have a record of this" is honest
4. **Never infer status from absence in the current message** — the full record may be elsewhere
5. **Apply ADEP-001 §7** — assumptions are assumptions, not facts. §9 — FACT ≠ ASSUMPTION ≠ INFERENCE

## Application

This applies to:
- Email trail summaries (check if events were already recorded)
- Stakeholder status claims (check STK records before stating engagement level)
- Timeline assertions (check daily memory files before stating what did/didn't happen)
- Initiative status (check INIT records before stating readiness level)
