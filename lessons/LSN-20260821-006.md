# Lesson: Point Fix ≠ System Fix — Schema Enforcement Must Be System-Wide

## Observation

The ACT schema formalization (commit 693b998) added `additionalProperties: false` to `action.schema.json`. This is the only schema in the system with this enforcement. Post-migration audit of all 18 schemas revealed:

- 16 schemas: `additionalProperties` NOT SET (defaults to true — allows arbitrary fields)
- 1 schema: `additionalProperties: true` (outcome.schema.json — explicitly allowing)
- 1 schema: `additionalProperties: false` (action.schema.json — the only enforced schema)

The same schema drift that produced 18 non-schema fields in ACT (requiring 135-record migration) is accumulating silently in every other record type right now.

## Root Cause

1. **One-at-a-time formalization** — Schemas were formalized individually, not as a batch. When one schema gets a fix, the others don't automatically inherit it.
2. **No system-wide enforcement gate** — There's no check that says "if one schema has additionalProperties: false, all must have it."
3. **Recurring pattern** — This is the third manifestation of the point-fix pattern:
   - LSN-20260821-002: Schema evolution without migration → existing records silently invalid (data layer)
   - LSN-20260821-005: SOP evolution without pairing → enforcement rules silently conflict (governance layer)
   - LSN-20260821-006: Schema enforcement without replication → non-schema fields accumulate silently (schema layer)

## Lesson

**A schema fix applied to one record type is a point fix, not a system fix.** When a pattern is identified and fixed in one type, immediately audit all other types for the same pattern. The cost of replication is low (add one line per schema); the cost of not replicating is silent accumulation across the entire system.

Schema enforcement is binary: either `additionalProperties: false` is set and non-schema fields are blocked, or it's not set and they accumulate. There is no partial enforcement.

## Generalization

The point-fix pattern applies to any system with multiple instances of the same control:
- Schemas: additionalProperties: false on one ≠ on all
- SOPs: version-locking on one pair ≠ on all pairs
- Records: field migration on one type ≠ on all types
- Taxonomy: namespaced tags on one domain ≠ on all domains

**Rule: When fixing an issue in one instance, immediately audit all other instances for the same issue. The fix is not complete until it's system-wide.**

## Fix Recommendation

1. **Immediate:** Add `additionalProperties: false` to all 17 remaining schemas
2. **Before enabling:** Audit each record type for non-schema fields (same process as ACT audit)
3. **Migration:** Migrate any non-schema fields found (same process as ACT migration)
4. **Verification:** Full validate.py run across all record types
5. **Institutionalisation:** Add to Engineered Success Framework: "Schema formalization is not complete until additionalProperties: false is set on all schemas in the system."
