# Lesson: Governance Drift in Paired SOPs

## Observation

Honcho's inductive analysis of the Aug 20 session identified a recurring behavioral pattern:

> Hermes demonstrates heightened awareness of governance drift risks when multiple SOPs govern the same pipeline, proactively identifying version mismatches and advocating for simultaneous version-locked updates to prevent conflicting enforcement rules.

Specifically: Template Discipline SOP (GOV-TEMPLATE-DISCIPLINE-001, v1.0) and Intake SOP (GOV-INTAKE-SOP-001, v1.1) govern the same CognitiveOS intake pipeline but were updated independently. This created version misalignment with conflicting enforcement rules for:
- Git staging procedures
- Pre-commit hook validation triggers
- Taxonomy validation requirements

## Root Cause

1. **Independent SOP updates** — Each SOP has its own version lifecycle. When one is patched, the paired SOP is not automatically checked for alignment.
2. **No version-locking gate** — There is no pre-commit or governance gate that checks whether paired SOPs are version-aligned before a governance change is committed.
3. **Implicit pairing** — The relationship between Template Discipline SOP and Intake SOP is implicit (they govern the same pipeline) rather than explicit (no `paired_with` field or cross-reference enforcement).

## Lesson

**Version-locking principle:** When two or more SOPs govern the same pipeline, they must be updated in the same commit with aligned version numbers. An independent update to one creates governance drift — conflicting enforcement rules that are invisible until a downstream operator encounters the contradiction.

This is the governance-layer analogue of LSN-20260821-002 (conformance drift in data records):
- LSN-20260821-002: Schema evolution without migration → existing records silently invalid
- LSN-20260821-005: SOP evolution without pairing → enforcement rules silently conflict

## Fix Recommendation

1. **Explicit pairing** — Add a `paired_sops` field to governance SOP records listing companion SOPs that govern the same pipeline
2. **Version-locking gate** — Pre-commit hook or governance check: if a governance SOP is modified, verify paired SOPs are also staged in the same commit OR explicitly flagged as deferred
3. **Version alignment** — Template Discipline SOP and Intake SOP should be brought to the same version number in a single commit

## Generalization

Any system with multiple governing documents for the same process is vulnerable to governance drift. The pattern:
1. SOP-A and SOP-B both govern Pipeline-X
2. SOP-A is updated to fix an issue in Pipeline-X
3. SOP-B retains old enforcement rules that now conflict with SOP-A
4. Operators encounter contradictory instructions → either follow one (wrong) or escalate (friction)

The fix is structural: make the pairing explicit and enforce same-commit updates.
