# Lesson

## Observation

The MQL framework session (12:04-12:10 UTC) demonstrated a clear leverage-point pattern. Four issues appeared to be separate problems:

1. Layer 2 budget ownership contention (DEC-20260822-002)
2. GTM funnel metrics undefined (ACT-20260822-004)
3. Layer 2 budget ownership unresolved (ACT-20260822-005)
4. Marketing capacity gap (RSK-20260822-004)

All four shared a common root: **no one had defined what marketing's deliverable actually was.** Without a defined deliverable, budget ownership can't be assigned, funnel metrics can't be built, and capacity can't be assessed.

A single definition — MQL = "requested a meeting" — collapsed all four issues at once:
- Budget ownership → marketing owns MQLs, budget justified against MQL output
- Funnel metrics → MQL is the handoff, each stage has an owner
- Capacity gap → specific MQL target makes capacity question concrete
- Tuesday meeting → one question replaces a debate

## Pattern

**Leverage-point definition:** When multiple open issues share a common definitional root, a single precise definition at the root can resolve several issues simultaneously. The effort is small (one definition), the impact is disproportionate (multiple issues resolved).

**Contrast with:** Addressing each issue individually (negotiate budget ownership separately, define funnel metrics separately, assess capacity separately, prepare for Tuesday separately) — more effort, less coherent outcome.

## Application

This pattern can be applied deliberately:
1. When facing multiple open issues, check whether they share a common root
2. Look for the undefined variable that connects them
3. Define it precisely
4. Let the definition propagate and resolve the issues
