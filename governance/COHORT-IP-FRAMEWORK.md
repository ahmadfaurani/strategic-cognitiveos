# Aras Cohort Joint IP Framework

**Authority:** DAF | **Established:** 2026-08-18 | **TLP:** AMBER | **Status:** Canonical

---

## 1. Governing Principle

Cohort Participants retain full ownership of their pre-existing Core IP. Aras retains full ownership of its pre-existing infrastructure, technology stack, engineering assets and platform IP. Where a participant's Core IP is jointly engineered, extended and operationalised by the Participant and Aras Engineering & Development Team using Aras infrastructure and technology capabilities, the newly created Foreground / Joint IP will be co-owned on a 50:50 basis.

This follows the established IP-collaboration distinction between **Background IP** — what each party brings into the collaboration — and **Foreground IP** — what is created through the collaboration. WIPO specifically identifies these concepts as central to collaborative development agreements.

---

## 2. IP Architecture

| IP Layer | Example | Ownership |
|----------|---------|-----------|
| **Participant Core IP** | Existing framework, methodology, algorithm, domain model, research, taxonomy, process | 100% Participant |
| **Aras Background IP** | AI infrastructure, platform architecture, orchestration, engineering frameworks, security components, deployment tooling | 100% Aras |
| **Third-Party IP** | Open-source models, libraries, commercial technologies | Original owner / applicable licence |
| **Joint Development IP** | New software, AI capability, algorithms, workflows, integration architecture, models, technical implementation created together | 50% Participant / 50% Aras |
| **Joint Product / Derivative Solution** | Deployable sovereign technology solution created from the joint development | 50% Participant / 50% Aras |
| **Project Know-How** | Technical discoveries, implementation methodologies and jointly developed design knowledge | Jointly controlled as contractually defined |

**Formal terms:** "Joint IP" or "Foreground IP" used as the formal contractual term rather than "Derivative IP," because "derivative work" has a more specific meaning under copyright law.

## 4. Critical Protection Boundary

**Non-negotiable:** Participation in the Cohort does not transfer ownership of either party's Background IP.

**Example:** If a participant enters with the R.I.S.I.K Framework, the R.I.S.I.K methodology remains their Core IP.

If Aras then builds:
- An AI reasoning engine around R.I.S.I.K
- Automated R.I.S.I.K analysis
- Agentic workflows
- Knowledge graphs
- Dashboards
- Inference architecture
- APIs
- Data pipelines
- Deployment architecture

The specifically agreed new technology created through the joint development programme becomes Joint IP.

Likewise, use of Aras' technology stack does not give the participant ownership of the underlying Aras platform, infrastructure, orchestration framework or pre-existing engineering assets.

## 5. Commercialisation Framework

### 5.1 Commercial Principles

| Commercial Matter | Proposed Principle |
|-------------------|--------------------|
| Joint IP ownership | 50% Aras / 50% Participant |
| Product licensing revenue | 50/50, subject to agreed deductions |
| IP sale / assignment | Mutual consent |
| Exclusive licensing | Mutual consent |
| Third-party sublicensing | Jointly governed |
| Internal research use | Permitted to both parties |
| Product roadmap | Joint Steering Committee |
| IP protection / filing | Joint decision |
| IP protection cost | 50/50 or recovered from commercial proceeds |
| Product branding | Jointly agreed |
| Customer implementation services | Revenue retained by performing party |
| Aras infrastructure / compute | Aras commercial revenue |
| Managed AI / cybersecurity services | Aras commercial revenue, unless otherwise agreed |
| Participant-specific professional services | Participant commercial revenue |
| Joint product licence / royalty | 50/50 Joint IP revenue |

### 5.2 Revenue Separation Principle

50:50 IP ownership does not mean every ringgit generated by the project is divided 50:50. This separation is strategically important for Aras — it protects the commercial attractiveness of the programme while still giving the IP creator genuine economic participation.

### 5.3 Worked Example

Assume a jointly developed sovereign AI product produces a RM2 million customer engagement:

| Revenue Component | Value | Treatment |
|-------------------|-------|-----------|
| Joint technology licence | RM600k | 50/50 (RM300k each) |
| Aras sovereign infrastructure | RM500k | Aras |
| Aras implementation | RM300k | Aras |
| Participant domain consultancy | RM200k | Participant |
| Managed AI/Security service | RM400k | Aras or agreed delivery party |

**Participant total:** RM500k (RM300k joint IP + RM200k consultancy)
**Aras total:** RM1.5M (RM300k joint IP + RM500k infrastructure + RM300k implementation + RM400k managed services)

## 7. IP Governance Gate

Every cohort project passes through a formal IP Declaration & Development Gate before engineering starts.

| Gate | Purpose |
|------|---------|
| **Gate 1 — Core IP Declaration** | Participant identifies what existed before entering the Cohort |
| **Gate 2 — Aras Background Technology Declaration** | Aras identifies relevant pre-existing technology being contributed |
| **Gate 3 — Joint Development Scope** | Both parties define exactly what they intend to create together |
| **Gate 4 — Contribution Register** | Engineering, datasets, algorithms, models, designs and other material contributions are recorded throughout development |
| **Gate 5 — Joint IP Determination** | Outputs falling within the agreed co-development scope are classified |
| **Gate 6 — IP Registration** | Copyright, patent, trademark, industrial design, trade-secret or contractual protection is determined as appropriate |
| **Gate 7 — Commercialisation Decision** | Continue R&D → Pilot → Productise → Licence → Deploy |

**Legal basis (Malaysia):**
- For patentable inventions, actual inventorship is recorded accurately. MyIPO states that where two or more persons jointly make an invention, patent rights belong jointly, and Malaysian patent law provides for joint patent ownership.
- Copyright and licensing arrangements are expressly documented rather than inferred informally.

## 8. Programme-Level IP Models

The governing framework is the umbrella. Each programme adapts it:

### PRG-001: PERJASA — Standard 50:50
- Individual participants bring domain IP (use cases, operational knowledge)
- Aras brings technology stack
- Prototypes built during workshop → Joint IP if they pass Gate 5
- Institution gets deployment licence; Aras retains platform IP

### PRG-002: CSM-Aras — Institutional JOM IP Register
- CSM brings operational domain IP (MyCERT threat response, cybersecurity expertise)
- Aras brings AI platform and engineering
- Joint IP tracked in JOM IP register (P3 AI Cyber R&D, P5 Capability Development)
- Institutional deployment vs external commercialisation per Section 5

### PRG-004: R.I.S.I.K × UiTM — Academic + Technology Joint IP
- UiTM brings R.I.S.I.K methodology (Core IP)
- Aras brings AI technology stack (Background IP)
- Joint platform IP = Foreground IP, 50:50
- MCMC funds the co-development (RM5M, 5 stage gates G1-G5)
- Each stage gate produces validated IP deliverables

### PRG-005: VORON-C2 — Work-for-Hire (Different Model)
- Interns are employees — what they build is work-for-hire, Aras owns 100%
- Creates alumni through skills dependency, not IP ownership
- Sovereign stack built by interns enters Aras IP portfolio directly
- Not force-fitted into the 50:50 model

## 9. Third-Party IP and Open-Source Licensing

Third-Party IP components (open-source models, libraries, commercial technologies) retain their original licences. Joint IP that incorporates Third-Party IP carries the licence obligations of those components.

Specific open-source licences used in the Aras technology stack should be reviewed by legal counsel to confirm compatibility with joint IP commercialisation terms.

## 10. Dispute Resolution

Tiered mechanism:

1. **Technical dispute** (Background vs Foreground classification) → Hadri + participant technical lead
2. **Strategic dispute** (commercialisation decisions, scope) → DAF + institutional sponsor
3. **Formal dispute** → Mediation
4. **Unresolved** → Arbitration

Disputes kept out of courts where possible. Technical disputes resolved at engineering level before escalation.

## 11. Strategic Cohort Proposition

**Bring Your IP. Build With Aras. Own What We Create Together.**

Structurally:

```
Cohort
  → Identify high-value Core IP
  → Match with Aras Engineering
  → Build on Aras sovereign infrastructure
  → Co-develop technology
  → Establish 50:50 Joint IP
  → Validate with real users
  → Productise
  → Deploy
  → Commercialise
  → Grow through Alumni Community
  → Alumni remain engaged through IP ownership
  → Enduring Strategic Ecosystem
```

The last element reconnects directly to the Alumni Community objective: alumni do not simply leave after completing a programme. They become a persistent IP, technology and deployment ecosystem around Aras.

Over multiple cohorts, the cumulative effect becomes:

**Alumni Network → IP Pipeline → Joint Technology Portfolio → Sovereign Deployment Opportunities → Managed Services → National Technology Ecosystem**

This is the central economic architecture of the entire Cohort Programme — not training revenue, but systematically discovering valuable domain IP and converting it through Aras' engineering capability into jointly owned, deployable sovereign technology.

## 12. Joint IP Register

Every joint IP asset created through a cohort programme is recorded in the Joint IP Register:

| Field | Description |
|-------|-------------|
| IP ID | Unique identifier (IP-PRG-NNN) |
| Programme | Which cohort programme produced it |
| Participant | Co-owning institution/individual |
| Title | Name of the IP asset |
| Description | What was built |
| Participant Core IP | What the participant brought |
| Aras Background IP | What Aras brought |
| Joint Development Scope | What was agreed to co-create |
| Gate Status | Which IP Governance Gate (1-7) the asset has passed |
| Pathway Stage | Prototype → Validated → Piloted → Commercialised → Deployed |
| Ownership Split | 50:50 (or variant if negotiated) |
| Commercialisation Mode | Institutional deployment / Joint commercialisation / Aras-led |
| Deploying Institution | Where the IP is deployed (if deployed) |
| Alumnus Responsible | Named alumnus who maintains the IP relationship |

The register lives in the cohort-programme repo and is updated as assets progress through the pathway.
