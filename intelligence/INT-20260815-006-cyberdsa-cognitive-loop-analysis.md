## STEP 8 — LEARN

### Learning Extraction Framework

This section defines what Ember should learn from this loop cycle and how it improves the next cycle.

#### Learning 1: Plan ≠ Execution

**Observation:** The CSM-Aras Stakeholder Coverage Plan is architecturally complete (5/8 metrics met by design) but operationally unactivated (3/8 at 0%). The gap between planning and execution is the primary risk vector.

**Lesson:** A plan without an enforcement mechanism is a document. The enforcement mechanism (tracker + weekly review + named owners for each action) must be created simultaneously with the plan, not as a follow-up.

**Institutionalisation:** Future intake of strategic plans must include an "Operationalisation Assessment" — which actions are plan-only vs execution-required, and what enforcement mechanism is defined.

#### Learning 2: Bottleneck Identification Should Trigger Immediate Action

**Observation:** DAF has been identified as carrying 45% of criteria across multiple analyses (INT-003, INT-005, this loop). The Programme Coordinator recommendation has appeared in every analysis. It has not been actioned.

**Lesson:** Identifying a bottleneck without removing it is analysis, not intelligence. If the same bottleneck appears in 3+ analyses without intervention, escalate from "recommendation" to "blocking alert."

**Institutionalisation:** Add to Cognitive Loop Step 5 (Prioritise): if a bottleneck is identified in 3+ consecutive cycles without action, flag as DECISION DEBT CRITICAL and force escalation.

#### Learning 3: Dependency Chains Are the Hidden Risk

**Observation:** The 193-org segmentation (2.1) has 6 downstream dependencies. The positioning sign-off (4.1) has 4. These chains are not visible when looking at individual criteria — only correlation analysis reveals them.

**Lesson:** Always map dependency chains, not just individual criteria. A single upstream blocker can paralyse an entire dimension.

**Institutionalisation:** For every future checkpoint, produce a dependency chain map showing which criteria block which downstream criteria.

#### Learning 4: Compounding Opportunities Should Be Prioritised Over Single-Impact Actions

**Observation:** Three compounding opportunities identified (segmentation framework, coverage tracker, positioning statement). Each unblocks 4-6 downstream criteria. These scored highest in the prioritisation engine.

**Lesson:** When multiple actions compete for priority, prefer compounding opportunities (one deliverable, multiple workstreams benefit) over single-impact actions.

**Institutionalisation:** Add "compounding score" (number of downstream criteria/workstreams unblocked) to prioritisation framework as an explicit dimension.

#### Learning 5: The Cognitive Loop Itself Adds Value

**Observation:** Running the 8-step loop produced insights that individual analyses did not:
- The correlation between coverage plan metrics and CP1 criteria (Step 3)
- The dependency chain from segmentation to signed POC (Step 3)
- The pattern of decision debt across 3 personnel decisions (Step 4)
- The compounding opportunity scoring (Step 5)

**Lesson:** The loop's value is in the connections between steps, not in any individual step. Sense alone is data. Classify alone is taxonomy. Correlate alone is mapping. The intelligence emerges from running all 8 steps in sequence.

**Institutionalisation:** Run the full 8-step loop at every checkpoint, not just ad hoc. The loop is the cognitive operating system, not a one-time analysis.
