## Findings Register

### 🔴 P0 (4)

1. **P0-TAX-01 — Canonical vocabulary duplication.** tags.yaml + dedicated YAMLs + schema enums maintained independently; live drift on mission (political-intelligence), readiness (3 disagreeing sets), portfolio (legacy strategic/tier-* still schema-permitted). One vocabulary should generate the others.
2. **P0-TAX-02 — Validator weaker than doctrine.** Pattern-based namespaces accept any kebab-case slug (validate_taxonomy.py L102-107). 16 open namespaces. Directly weakens Rule 1 of the 5-rule protocol adopted in DEC-20260908-004.
3. **P0-TAX-03 — No full JSON Schema enforcement.** Enum mismatches = P1 warnings; record passes on zero P0. additionalProperties:false declared but not machine-enforced. "Validator green" (899 files / 0 violations) is true but weaker than it sounds.
4. **P0-TAX-04 — Untyped semantic facets.** mission_alignment accepts arbitrary strings; mixes mission/domain/capability dimensions. *Ember scope correction: 8 affected records, not 1.* Breaks deterministic retrieval for Honcho/OpenViking.

### 🟠 P1 (3)

5. **Synonym debt** — implicit near-synonyms across domain vocabulary; explicit alias model proposed (aliases + deprecated_aliases per canonical value).
6. **Index coverage** — 86% is respectable for a repository, a bottleneck for a memory harness; ≥95% proposed as maturity gate.
7. **Closed/extensible namespace policy** — two namespace modes so operational flexibility stops silently expanding the ontology.

### 🟡 P2 (3)

8. Temporal ontology management (deprecated / replaced_by / valid_from / valid_to).
9. Taxonomy version stamping on records and index builds.
10. Taxonomy regression tests to prevent future drift.

### Ember corrections and additions (verification pass)

- Semantic leakage count corrected 1 → **8 records** (listed in findings).
- Legacy tier-* values present in **10+ engagement/decision records** — P0 remediation must include a paired data-migration pass, not schema surgery alone.
- `tier: strategic` unused in records — safe to remove from schema.
- **P0 re-sequencing:** JSON Schema enforcement first. It is the cheapest fix (library already installed), is a precondition for honest validation of every subsequent change, and converts the audit's "validator green ≠ conformity" finding into a measurable pass/fail immediately.
- Auditor confirmed read-only (no repo changes). Access boundary for any follow-on work: fork + PR, per DEC-20260908-004.

## Athena's Proposed Target Model (recorded for per-item review)

Retain existing architecture; insert a canonical machine-readable registry (`taxonomy/registry.yaml`) as L1, **generating** taxonomy views, schema enums/constraints, and validator rules — instead of three separately maintained representations. Positioning: CognitiveOS = Canonical Semantic Memory; Taxonomy = Cognitive Addressing System; Indexes/Graph/Embeddings = Retrieval Plane; Honcho/OpenViking = Memory Interpretation & Validation Plane; Agents = consumers/producers of governed memory.

Projected effect of the 4 P0 fixes: 7.2 → >9/10 memory-harness readiness without redesign. Offered next step: Taxonomy V2 engineering specification (canonical schema, namespace hierarchy, alias/deprecation model, validator logic, migration rules, automated tests) drafted against this repo before touching records.
