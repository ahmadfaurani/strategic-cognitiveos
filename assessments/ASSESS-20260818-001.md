# Assessment Record

## Assessment Target
R.I.S.I.K Framework AI enablement — mapping AI capabilities to doctrine layers and KKOM build stages, prepared as input to the Operational Development Alignment Session.

## Doctrine Compliance Constraints (from §2.5)

All proposed AI capabilities MUST satisfy:
1. **Accountability stays with the analyst** — AI output is not a source, cannot be cited as one
2. **Every AI-originated claim traced to original source and verified** before entering any report
3. **Analyst must be able to review, question, and reject AI suggestions** — tools that don't allow this are unsuitable
4. **Declare to recipient when AI materially influences a product**
5. **Treat monitored materials as untrusted** when fed into AI tools (prompt injection risk per §2.5.5)
6. **AI is NOT a fourth discipline** — it's a tool, threat surface, and cross-cutting factor

## Per-Layer AI Capability Map

| Layer | AI Capability | Doctrine Alignment |
|-------|-------------|-------------------|
| **R — Risikan** | Automated signal collection (OSINT/SOCMINT), multi-language coverage, signal clustering, pattern detection, narrative classification (5-type ladder), source grading assistance, LLM reference checking | §2.5.1 — AI as tool. Accelerates collection. Gate 1 (Kelayakan) intact. "Ask the chatbot" (§2.5.4) is NEW intelligence requirement. |
| **I — Isu** | AI-assisted signal grouping, issue boundary suggestion, neutral naming assistance, triage scoring support | Human makes all three decisions. AI drafts, human decides. |
| **S — Sentimen** | Automated sentiment analysis, trend detection, baseline computation, anomaly flagging | Must declare AI influence on product. Analyst can review and reject. |
| **I — Influens** | Actor network mapping, SAMAR behavioural indicator detection, coordinated inauthentic behaviour detection | AI surfaces candidates, human confirms. 3+ converging signals required for coordination claims. |
| **K — Kontra-naratif** | Response option generation, narrative ladder position assessment, effectiveness prediction | Gates 3 and 4 are human decisions. AI informs but doesn't decide. |

## Three Priority Use Cases

### Use Case 1: Signal Collection & Grading Engine (Layer R)
- **Scope:** Automate OSINT/SOCMINT collection across Malaysian media landscape. Auto-grade sources A-F per doctrine. Auto-classify narratives per 5-type escalation ladder. Auto-detect SAMAR behavioural indicators.
- **Output:** Pre-populated Borang Isyarat (Signal Forms) for analyst review
- **Why first:** Layer R is the foundation — everything depends on signal quality. Highest AI leverage. Clearest doctrine alignment.
- **Doctrine compliance:** Analyst reviews every signal. AI never grades its own output as source. Human Gate 1 intact.
- **KKOM stage mapping:** Stage 1 (Data Foundation) + Stage 2 (Back-end + API)

### Use Case 2: Issue Decomposition Assistant (Layer I)
- **Scope:** AI-assisted signal grouping (which signals belong together?), issue boundary suggestion (what's in/out?), neutral naming drafts (avoiding framed language), triage score calculation (sensitivity × reach).
- **Output:** Draft Kad Isu (Issue Card) for analyst review
- **Why second:** Most damaging error at Layer I is treating one conversation as one issue. AI can surface component issues by clustering signals by audience, cause, and verifiability.
- **Doctrine compliance:** Human makes all three decisions (grouping, bounding, naming). AI drafts, human decides.
- **KKOM stage mapping:** Stage 2 (computation engine)

### Use Case 3: Reference Poisoning Monitor (NEW — from §2.5.4)
- **Scope:** Monitor what major AI chatbots say about monitored entities/issues. Track changes in AI-generated responses over time. Detect potential LLM grooming campaigns (coordinated content flooding). Flag when monitored narratives appear in AI chatbot responses.
- **Output:** "AI Environment Signal" — new signal type for Layer R
- **Why this matters:** The doctrine explicitly identifies this as a new intelligence requirement not in any existing framework. No other information operations framework addresses this.
- **First-mover advantage:** This capability doesn't exist in any commercial product. R.I.S.I.K would be the first doctrine to operationalize it.
- **KKOM stage mapping:** Stage 2 (computation) + Stage 5 (Integration)
