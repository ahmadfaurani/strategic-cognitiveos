## 📋 OPERATIONAL WORKFLOW

### 4-Phase Process

```
Phase 1: Intelligence Collection (48 min)
  ↓
Phase 2: Content Synthesis (35 min)
  ↓
Phase 3: Git Repository Creation (15 min)
  ↓
Phase 4: Quality Assurance (30 min)
  ↓
DEPLOYED (128 min total)
```

### Phase 1: Intelligence Collection (48 minutes)

**Inputs:**
- Candidate/constituency name
- Election date
- Strategic priorities

**Process:**
1. Web searches (candidate + party + constituency)
2. Social media profile fetching
3. News article extraction
4. Opposition research
5. Historical election data collection

**Outputs:**
- Research notes (memory/<date>-<topic>.md)
- Signal registry (memory/signals/YYYY/MM/DD-signals.jsonl)
- Source documentation (40+ sources)

**Automation Level:** 95%  
**Human Review:** 5% (source validation)

### Phase 2: Content Synthesis (35 minutes)

**Inputs:**
- Research notes
- Signal registry
- Standard templates

**Process:**
1. Retrieve research (memory_search)
2. Generate structured content (LLM)
3. Apply classification headers
4. Insert vulnerability assessments
5. Add actionable recommendations
6. Include success metrics

**Outputs:**
- Draft documents (workspace/<repo>/<path>.md)
- Candidate profiles (standard 6-section template)
- Strategic documents

**Automation Level:** 85%  
**Human Review:** 15% (tone, accuracy)

### Phase 3: Git Repository Creation (15 minutes)

**Inputs:**
- Draft documents
- Git token
- GitHub credentials

**Process:**
1. Initialize Git repository
2. Create directory structure
3. Organize files (folders)
4. Git commits (logical grouping)
5. Push to GitHub

**Outputs:**
- GitHub repository (private)
- Clean commit history
- Version-controlled intelligence

**Automation Level:** 90%  
**Human Review:** 10% (commit messages)

### Phase 4: Quality Assurance (30 minutes)

**Inputs:**
- Deployed repository
- Verification checklist
- Human reviewer

**Process:**
1. File count audit
2. Spot-check content (20% sample)
3. Fact-checking (90%+ target)
4. Security verification (PRIVATE, 2FA)
5. Approval sign-off

**Outputs:**
- Certified repository
- Quality metrics
- Update schedule

**Automation Level:** 70%

## 🔐 SECURITY PROTOCOLS

### Classification Levels

| Level | Definition | Access | Storage |
|-------|------------|--------|---------|
| **INTERNAL** | Campaign strategy, candidate profiles | All campaign staff | Private GitHub |
| **RESTRICTED** | Opposition research, vulnerability intel | War Room leads only | Separate private repo |
| **CONFIDENTIAL** | Personal data, financial info | Campaign Director only | Encrypted, offline |

### Access Control

**GitHub Repository Settings:**
- Visibility: PRIVATE
- Collaborators: Whitelist only
- 2FA: Required for all users
- Branch Protection: main branch (PR required)
- No Forks: Prevent external copies

**Leak Response Protocol:**
- IMMEDIATE (0-1h): Notify War Room Chief, emergency meeting
- SHORT-TERM (1-4h): Damage assessment, source identification
- MEDIUM-TERM (4-24h): Public response (if needed), security audit

## 🔧 TROUBLESHOOTING

### Common Issues & Solutions

| Issue | Problem | Solution |
|-------|---------|----------|
| **Web Search Quality** | Returns irrelevant content (porn, products) | Refine query (add "PKR", "election"), use domain_filter |
| **Facebook Fetch** | DNS resolution fails (getaddrinfo EAI_AGAIN) | Retry with different DNS, use Instagram/Twitter alternative |
| **Git Authentication** | Token authentication fails | Verify token permissions, regenerate token |
| **LLM Accuracy** | Factual errors in profiles | Increase verification threshold (90% → 95%), add primary sources |
| **File Organization** | Files in wrong folders | Use standardized directory structure |
| **GitHub Visibility** | Repository accidentally public | Double-check Settings > General > Visibility |
