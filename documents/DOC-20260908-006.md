# DOC-20260908-006 — Taxonomy Index Development Framework

## 1. Purpose

Establish the structured analytical approach for developing the taxonomy index of the canonical repository (`strategic-cognitiveos`, per DEC-20260908-004), with a measurable baseline and a governed evolution protocol.

## 2. Three Analytical Layers

| Layer | Content | Governance |
|-------|---------|------------|
| **L1 Controlled Vocabulary** | `taxonomy/*.yaml` — 7 files, ~20 namespaces (mission, domain, org, product, status, readiness, type, role, risk, portfolio-tiers, priorities, sensitivity) | Changed only via validator-gated commits (Rule 1) |
| **L2 Structural Facets** | 17 canonical record directories (SOP §3 matrix); record schema (universal base + type fields); pair-lock invariants | Pre-commit hook: schema + taxonomy + pair-lock |
| **L3 Derivation / Index Layer** | 20 index files (action, decision, document, initiative, stakeholder, organization, risk, lesson, opportunity, commitment, outcome, assessment, intelligence, product-readiness, executive-portfolio, PIR, unresolved-questions) | Hybrid: machine-regenerable rows + human commentary; reconciled quarterly (Rule 4) |

Analytical stance: L1 answers "what vocabulary exists", L2 answers "how records are shaped", L3 answers "what is retrievable". Taxonomy health = consistency between layers, measured by validator status (L1↔L2) and orphan rate (L2→L3).

## 3. Baseline (2026-09-08, measured)

- **Records:** 570 active (ACT 210 / DEC 79 / STK 109 / RSK 52 / INIT 38 / DOC 33 / ART 33 / ORG 24 / CMT 24 / LSN 18 / ASSESS 14 / OPP 8 / CONV 3 / OUT 3)
- **Indexes:** 20 files, 1,845 lines; 8 refreshed Sep 8; organization-index stalest (Sep 4)
- **Validator:** 899 files, 0 taxonomy violations (tool: `tools/validate_taxonomy.py`, `tools/validate.py`)
- **Index coverage:** 490/570 = 86%; orphans 80 (actions 45, organizations 18, stakeholders 13, decisions 2, risks 1, lessons 1). Note: org/stakeholder orphans partly a measurement artifact (some indexes list names, not IDs) — reconciliation resolves this rather than assuming true orphanage.

## 4. The 5-Rule Protocol (adopted in DEC-20260908-004)

1. **Validator-gated vocabulary** — new tag/namespace value requires `taxonomy/*.yaml` entry + passing validator run in the same commit. No uncontrolled tags (DEC-20260818-013 lineage).
2. **Commit-time index discipline** — a record commit without its index row is incomplete; weekly orphan scan rides SOP-AV-001; target <5% orphans.
3. **Single-source rule** — satellite repos and the workspace root hold working artifacts; strategic state must exist as a CognitiveOS record with provenance link. No strategic state outside the canonical repo.
4. **Quarterly reconciliation** — regenerate index rows from records on disk (next: 2026-10-01), preserving human commentary blocks; log deltas in each index changelog.
5. **Declared-purpose branches** — every branch states its role in its first commit; current model: `main` (records), `memory-mirror` (agent continuity).

## 5. Reconciliation Priorities (data-driven)

| P | Target | Basis |
|---|--------|-------|
| P1 | Rebuild organization-index | Stalest index (Sep 4) + highest orphan rate (18/24) |
| P2 | Actions orphan batch (45) | Largest absolute orphan count; cross-check related_records chains |
| P3 | Stakeholder backfill (13) | Feeds Amelia 77-person activation tracking |
| P4 | Decisions/risks/lessons stragglers (4) | Trivial closure |

## 6. Success Metrics (review at Sep 30 Honcho three-layer checkpoint)

- Orphan rate <5% (from 14%)
- Validator green maintained (899+ files, 0 violations)
- Zero strategic state outside canonical repo (audit-verifiable)
- Index freshness: every index ≤14 days behind its newest record
