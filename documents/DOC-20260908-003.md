## FTE Capacity Model (Section 2) — the headline

| Phase | Window | Required FTE | Headcount Envelope |
|-------|--------|--------------|--------------------|
| Phase 0 — Secure baseline | Days 0–5 | 7 | MYR 1.2–1.8M |
| Phase 1 — Pilot readiness | Weeks 1–4 | 7 (planning floor for 4-week target) | MYR 1.2–1.8M |
| Phase 1B — Controlled pilot | Weeks 5–8 | 7 | MYR 1.2–1.8M |
| Phase 2 — Productisation/Beta | Months 3–5 | 12 | MYR 3.5–4.5M |
| Phase 3 — GA | Months 9–15 | 18 | MYR 5.5–7.0M |
| Scale | Months 15–24+ | 28+ | MYR 9–12M |

7-FTE coverage blocks: Product/programme 1.0, Eng leadership 1.0, App engineering 1.5, Data/intel engineering 1.0, Frontend/UX 0.5, QA/release verification 1.0, Security/privacy/continuity 0.5, Platform ops/support 0.5.

**"Can five FTE deliver?"** — plan's own answer: only as a constrained case (combined roles, deferred non-gate work, extended schedule); critical security/evidence controls are not waived. 5-FTE is NOT the preferred capacity for the 4-week readiness target.

**Independence constraints (§2.4):** on-call primary ≠ secondary; QA challenger ≠ implementer; security owner ≠ change applier; pilot support ≠ sole technical responder; admin config ≠ audit review. Minimum named-person posture: ~7 contributors with overlap.

**Hiring sequence:** (1) Lead Engineer Phase 0, (2) Data Engineer Phase 0, (3) Designer/Frontend Phase 1, (4) fractional DPO pre-pilot, (5) CISO contractor Phase 1–2, (6) ring-fenced QA/ops immediately, (7+) L&C/CS/Intel Lead at Phase 2.

## Gate Framework

Phase gates: Phase 0 Secure baseline (Pass/Hold) → Phase 1 Pilot ready (Go/Conditional/No-Go) → Phase 1B Pilot complete (Remediate/Productise/Extend/Stop) → Phase 2 Production ready → Phase 3 Capability release. Open gates per v1.1: **deployment parity, TLS reachability, named accounts, supplier disposition, anonymised-network decision**. C1 (credential closure) recorded CLOSED (BLK-001) on operator confirmation. Phase 0 gate requires: rotated credentials, release identity, access/incident readiness.

## Key Operational Positions

- T0-relative sequencing ("management windows, not commitments where staffing or customer availability remains unconfirmed") — T0 anchor date not set
- Release: manual promotion from approved manifest pre-pilot; no opportunistic server edits; 2 named deployment traps (persistent server edits; Compose-not-passed config)
- Backup/restore: documented tested restore is an identified productisation gap — "a successful backup job is not proof of recoverability"
- No contractual SLAs until measurement and support capacity are proven (internal targets only)
- Pilot UAT: up to 10 representative real cases, defined journeys, pass/conditional/hold dispositions
