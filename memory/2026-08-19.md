## 11:16–16:03 UTC — Cognitive Loop Review → Actionable Intelligence (§7) → Engineered Success (§9)

**Source:** DAF ↔ Ember, Telegram direct
**Trigger:** DAF requested Cognitive Loop Review, then §7 Actionable Intelligence Protocol, then §9 Engineered Success Framework

### What Happened (3 cascade failures discovered and fixed)

**Failure 1 (Deriver zero observations, 08:51–11:23 UTC):** Qwen3.6-35B-A3B is a reasoning model. Default `MAX_OUTPUT_TOKENS=4096` too small — model spends entire budget on `reasoning_content`, returns `content: null` with `finish_reason: "length"`. JSON parser receives empty string → "Repair failed." 2.5h silent failure, container showed "healthy" throughout.

**Failure 2 (TEI embedding connection refused, since initial deployment):** `.env` had `EMBEDDING_BASE_URL=http://127.0.0.1:8082/v1` — host port, unreachable from inside Docker containers. TEI was reachable via Docker DNS (`tei-embeddings:80`) the entire time. This mismatch existed since initial TEI deployment, only surfaced when deriver was recreated.

**Failure 3 (Embedding backlog permanently stalled, discovered during §9):** All 1,946 unembedded messages hit `MAX_SYNC_ATTEMPTS=20` during the 2.5h deriver failure window. Reconciler marked them `sync_state='failed'`. Reconciler only processes `sync_state='pending'` — permanently skips `'failed'`. My Cognitive Loop Review claim "self-heal overnight" was **wrong**.

### Fixes Applied

1. `DERIVER_MODEL_CONFIG__MAX_OUTPUT_TOKENS` uncommented, set to 8192 (was default 4096)
2. `EMBEDDING_MODEL_CONFIG__OVERRIDES__BASE_URL` changed from `http://127.0.0.1:8082/v1` → `http://tei-embeddings:80/v1` (Docker DNS)
3. Reset 1,946 failed rows: `UPDATE message_embeddings SET sync_state='pending', sync_attempts=0 WHERE sync_state='failed' AND embedding IS NULL`
4. All Qwen3.6-35B-A3B references changed to Qwen3.6-27B (DAF directive, 15:32 UTC). 5 config lines updated: deriver, dialectic minimal, dialectic low, summary, comments.
5. TEI integrated into `docker-compose.yml` (was standalone `docker run`). Service: `tei-embeddings`, image `ghcr.io/huggingface/text-embeddings-inference:cpu-latest`, volume `tei-cache:/data` (persistent model cache), healthcheck `curl -sf http://localhost:80/health`.
6. Deriver monitoring cron created: `tools/deriver-health-check.sh` every 15 min via OpenClaw cron. Alerts if 3+ zero-observation cycles in 30 min.

### Key Lessons
1. "Self-heal overnight" was wrong — `MAX_SYNC_ATTEMPTS=20` converts transient failures to permanent silent failures. Must check `sync_state` distribution, not just count.
2. Docker containers cannot reach host ports via `127.0.0.1`. Must use Docker DNS (`container-name:port`).
3. TEI needs persistent volume (`tei-cache:/data`) or model re-downloads ~2GB on every restart.
4. Container "healthy" means process running, not producing value. Need output validation, not just availability checks.
5. My original Cognitive Loop Review misdiagnosed the TEI issue as "lost batch flag" — actual root cause was Docker networking mismatch. Corrected in §7 package.
